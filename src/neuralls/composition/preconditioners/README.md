# Preconditioners

Turns a preconditioner configuration into a torchalg preconditioner for a matrix in a given format. This is the only place that translates config models into solver objects.

## Modules

- `factory.py`: `create_preconditioner`/`create_preconditioner_with_coarsening` are the single construction path. Both just resolve the matrix format (`_resolve_format_input`, `builders.py`), look up the `(type, matrix format)` builder (`_lookup_builder`), and call it — every builder returns `(Preconditioner, CoarseningStrategy | None)`, so the table is the only dispatch mechanism; no type gets a special case before it.
- `builders.py`: the per-`(type, matrix format)` builder registry (`_BUILDERS`) and all 18 `_build_*` functions it dispatches to. Every builder constructs its `torchalg.Preconditioner` with hyperparameters only, then calls `.setup()` before returning — `torchalg`'s two-phase contract requires an explicit `setup()` call before `apply()` for every preconditioner kind, so `create_preconditioner`/`create_preconditioner_with_coarsening` always hand back an already-`setup()`, ready-to-apply preconditioner. Most builders call `.setup(matrix)` (a `torchalg.MatrixSetupPreconditioner` — Jacobi/ILU/IC0/every AMG variant: setup genuinely depends on the matrix's values). `_build_neural` never calls `setup()` (torchalg's `NeuralPreconditioner` is a `StaticSetupPreconditioner` built on an already-loaded predictor, so it is ready after construction and never reads the matrix); the predictor is loaded ahead of the timed build via `checkpoint_store.py`/`preloading.py`, like every checkpoint-backed kind, and borrowed by a `DLKitNeuralPreconditioner`, or loaded in the builder and owned by an `OwningDLKitNeuralPreconditioner` when nothing was preloaded; `_build_identity` never calls `setup()` at all since `Identity.__init__` already marks itself ready. Dense AMG's builder (`_build_dense_amg`) is the one whose coarsening is a real object rather than `None`, because the realized coarse dimension is only known from that object. `_DENSIFY_FOR_CSR` names the dense-only types (neural, neural AMG) that get their CSR input densified first, with one `O(n^2)` warning.
- `coarsening.py`: AMG coarsening-strategy construction (`_build_amg_coarsening`), dispatched per kind: target-dimension search, POD-2G (reconstructed from a fitted checkpoint, or fit inline from snapshots), neural POD-2G (fit on a model's predictions), and aggregation. A checkpoint is read from `active_checkpoint_path`, which prefers the resolved MLflow artifact. Inline fit arrays may be staged by `PreconditionerService` before setup timing and are passed into the builder, so dataset reads never inflate the online setup measurement.
- `schedule.py`: `create_scheduled_preconditioner` wraps an already-`setup()` primary preconditioner in a `ScheduledPreconditioner` that switches to a fallback after `PreconditionerScheduleConfig.limit_iters`, or does nothing if unscheduled. When the primary is already ready (as all factory builders return it), the wrapper prepares only its fallback and marks itself ready; this keeps one real setup per scheduled matrix workload.
- `pod_fittable.py`: the dlkit `Fittable` adapter over torchalg's `PODCoarseningStrategy`. It must stay importable at its module path, because `FitJobConfig` jobs reference it by name.
- `_weighting.py`: maps `SnapshotWeightingConfig` to torchalg's POD row-scale functions.

The sparse AMG preset builds its aggregation internally, so for CSR AMG the coarsening is `None`.
- `checkpoint_store.py`: `CheckpointStore` (owns loaded POD bases and predictors and releases each predictor once), the read-only `PreloadedCheckpoints` protocol builders consume (`NO_PRELOADED` null object by default), typed keys (`PodBasisKey`, `PredictorKey`) and `preloaded_inference_factory`. Builders borrow the store's predictors: torchalg's `NeuralPreconditioner` and neural coarsening never release a predictor they were given, so a discarded timing repeat cannot unload a shared model. Only neural POD-2G's `with factory(path) as predictor:` releases on exit, so it gets a non-owning view.
- `preloading.py`: `preload_checkpoints` loads every checkpoint a config exposes through `CheckpointRefBearing`, using the `_REF_PRELOADERS` mapping (ref type to loader); a checkpoint kind without an entry fails loudly.
