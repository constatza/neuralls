# Domain Presentation

What datasets, methods, and comparison cohorts are called, as typed values. The
vocabulary (facts, the fact catalog, notation policy, rendering of one
`ScientificDescription`) lives in `shared/scientific_description/`; this package owns
the parts that know what a dataset, a dataset-trained method, or a title is.

- `provenance.py`: `DatasetSourceProvenance`, `StrategyProvenance` (realized `rows`, algorithmic `parameters`, closed `StrategySeed = ExplicitSeed | DerivedSeed | NoSeed`; its `facts` derive the `N` and `s` facts so a count or seed cannot be stored twice), `DatasetGenerationProvenance` (unique strategy kinds whose rows sum to `generated_rows`, plus the `root_seed` that derived streams come from) and `DatasetPresentation`.
- `strategy_names.py`: `strategy_base_name`, the exhaustive controlled display name of each `GenerationStrategyKind`.
- `qualifier.py`: `dataset_qualifier` describes a dataset by its strategies; a single strategy's `N` is the dataset total, a mixture adds a leading `Mixture (N=…)` description. Seeds stay in the structured provenance only.
- `titles.py`: the validated `EditorialPresentation`, `ComparisonScopePresentation`, and the closed `ComparisonTitle` union. A training or evaluation session gets `session_title(titles)`: the one shared title, or a `CollectionTitle` of at least two distinct titles. A comparison session gets `summarized_session_title(titles, SessionCounts)`: a lone system keeps its own title; otherwise a `SummarizedTitle` carries the shared title (when every system has the same one) and the system, RHS-type and matrix counts, so a session never enumerates its systems (`SessionTitle`).
- `run_names.py`: what an MLflow run is named after, as typed values, never text. `SessionRunName`, `ComparisonRunName` (a `ComparisonSubject = ComparisonScopePresentation | EditorialComparison`, so an editorial title is followed by the dataset it ran on; `SystemQualifier` of `HeldOutMatrixPart`/`RhsDrawPart`, and a `RunStamp = RunTimestamp | Untimed`), `MethodRunName` (a `ConfiguredMethodPresentation`), `TrainingRunName` and `EvaluationRunName` (a `TrainingSubject = DatasetQualifiedMethodPresentation | EditorialTrainingSubject`) form the closed `RunName` union. `NamedRun` pairs a name with the case's `NotationPolicy`. `TrainingPresentation` is the subject plus notation that training and evaluation carry. `platform/tracking/run_names.py` renders these at the tracking sink.
- `recipes.py`: `render_recipe`, the text of an `RhsRecipe` (shared/rhs_recipe.py): the kind in words, parameters (μ, σ, ω, mask ρ) in the case's `NotationPolicy`; a standard-normal, unmasked recipe shows no parameters.
- `methods.py`: the presentation lifecycle. `StandaloneMethodPresentation` / `DatasetQualifiedMethodPresentation` (closed union `ConfiguredMethodPresentation`; only the qualified variant owns a `DatasetPresentation`), `UnvalidatedComparisonPresentation` -> `PreparedComparisonPresentation`; a finished workload reports one `ExecutedMethod` (the prepared method plus its `SystemRealization`s, unique by system id and empty when no setup succeeded). Prepared and executed types validate on construction, so they cannot be built around `planner.py`: unique fact keys in `SystemRealization` and `compact_facts`, and `compact_facts` must be an ordered subsequence of the configured facts. `PreparedMethodPresentation.compact_identity()` is a frozen `CompactIdentity` of typed `(key, kind, value)` fact identities, so a rank of `10` and a rank of `10.0` are different methods. No state stores rendered text, and assignment identity is never a fact.
- `planner.py`: the pure transitions. `prepare_presentations` turns an unvalidated cohort into the only state execution and tracking accept: it keeps every algorithmic fact, scheduling facts (describers emit them only when non-default), and a reproducibility fact such as a seed only when its value differs between methods of the same family. Collisions are decided on structured compact facts plus the dataset qualifier, never on rendered text, and raise `DuplicateMethodPresentationError` before any run opens. `reduce_realized_facts(systems, population)` keeps only facts equal on every system of a population and keeps nothing unless every system of the population was realized, so a group label never claims a matrix-varying value nor one known for only the systems whose setup succeeded. The compact-by-policy decision (`FactVisibility` -> bool) is made once by `shared/scientific_description/catalog.py::is_compact_by_policy`; the planner, the dataset qualifier, and group reporting all use it.
- `render.py`: `render_method` (appends the training dataset exactly once), `render_dataset`, and `render_title`, built on the shared `render`; `render_distinct_methods` renders a set of methods so different methods never share a text, re-rendering with more significant digits the decimals of methods that collide only through rounding, and raising `IndistinguishableMethodsError` if they stay identical at full precision. `MissingMethodPresentationError` is raised wherever a method's presentation is required and absent.

Import from these submodules directly; `__init__.py` re-exports nothing.
